# V0.3 Adaptive Repair Routing — executable policy and how to run it

This implements a **ticket-count-aware repair stage**, using the latest
independently VALIDATED Sol ticket packet. Deterministic routes:

| Outstanding tickets | Repair route | Implementation agent |
| --- | --- | --- |
| 0 | NO_REPAIR | None; check release gates |
| 1–4 | CODEX_DIRECT | ONE GPT-6.1 Sol High **workspace-write** implementer |
| 5+ | AGY_PARALLEL | Herdr/cbds with max 2 file-isolated AGY workers |
| Any P0 or DISPUTED | MANUAL_TRIAGE | Risk/requirements decision first |

\`--force-multi\` overrides 1–4 to AGY for complex file ownership.
No route ever authorizes merges, deployment, token-limit bypasses or
self-approval. The implementation agent and independent read-only reviewer
must be separate processes with distinct evidence.

## 1. Check the reviewed ticket input

The ticket JSON MUST already have passed
\`scripts/validate-sol-tickets.py\` against the actual reviewed SHA and
checkout. A report with exit 27 is a successful CODE review returning FAIL;
an invalid packet or BLOCKED result is not eligible for routing.

\`\`\`bash
cd /home/openclaw/agent-orchestration-lab
python3 scripts/route-repair.py \
  --tickets /ACTUAL/VALIDATED/review-dir/tickets.json \
  --state /ACTUAL/NUTRISNAP/WORKTREE/.cbds/review-loop-v02.json
\`\`\`

If the state matches the packet, the router preserves all existing
\`open_tickets\` and prior OPEN/REGRESSED/DISPUTED dispositions.
A missing/wrong SHA fails closed. Without matching state, omit \`--state\`
only when the campaign genuinely has no state file; do not hide old tickets.

The JSON includes route, open ticket count/IDs, implementation model and
sandbox, and whether the current review budget is exhausted. The router never
calls models, creates cbds tasks, or changes Git state.

## 2. CODEX_DIRECT audit trail / integration gate

The coordinator first ensures a clean isolated branch/worktree excluded
from the daily automatic 6 AM merge to main, verifies the exact baseline,
and produces a concise ticket-specific prompt. Example call:

\`\`\`bash
codex exec --model gpt-6.1-sol --sandbox workspace-write \
  -C /ABSOLUTE/REPAIR/WORKTREE \
  --output-last-message /ABSOLUTE/STATE/codex-implementation.log \
  - < /ABSOLUTE/STATE/focused-repair-prompt.md
\`\`\`

Codex implementation should reproduce each defect, add regression tests,
make bounded changes and report what it actually ran. The COORDINATOR then
inspects the diff, runs all focused/real-Postgres tests, typecheck and build,
and commits on the isolated feature branch only. Production databases are
forbidden.

The coordinator writes a real JSON implementation attestation OUTSIDE
tracked source, after verifying the new full HEAD SHA, previous reviewer
SHA, tickets, model/sandbox and nonempty Codex run log:

\`\`\`json
{
  "route": "CODEX_DIRECT",
  "implementation_sha": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "review_baseline_sha": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb",
  "model": "gpt-6.1-sol",
  "sandbox": "workspace-write",
  "ticket_ids": ["SOL-R001-007", "SOL-R004-016"],
  "implementation_log": "/ABSOLUTE/STATE/codex-implementation.log"
}
\`\`\`

Replace ALL placeholders with the real values. The ticket IDs must cover
the existing review-loop open-ticket ledger; do not delete/close a ticket
without a new independent review disposition.

Update the same existing review-loop campaign (when it still has an
authorized, unexhausted review budget) using **exactly one** provenance mode:

\`\`\`bash
python3 /home/openclaw/agent-orchestration-lab/scripts/review-loop-gate.py integrate \
  --repo /ABSOLUTE/REPAIR/WORKTREE \
  --test-evidence /ABSOLUTE/STATE/integrated-software-tests.log \
  --codex-implementation-evidence /ABSOLUTE/STATE/codex-implementation.json
\`\`\`

For AGY_PARALLEL, use the original \`--cbds-report-ids real1,real2\`
instead of \`--codex-implementation-evidence\`. Providing both fails closed.
The gate checks Codex JSON's exact SHA, baseline, ticket coverage, sandbox,
model and nonempty log, while retaining the hard review-count cap.

**Important:** R004's five authorized independent reviews are ALREADY
exhausted. The focused Codex repair after 5/5 does not retroactively add
another review or let \`review-loop-gate.py integrate\` succeed on that
exhausted state. Do not reset it or fabricate a new budget. A future
independent review requires new explicit owner authorization, creating a
separately identifiable new campaign and preserving R004's immutable
five-review history and 4-ticket closing checkpoint.

## 3. Independent review and release

After tests and a fresh integrated SHA, and only under an authorized
unexhausted review campaign, invoke \`scripts/run-sol-review.sh\` in
\`SOL_REVIEW_TICKET_MODE=1\` with a read-only profile. Validate JSON,
update the review ledger, and rerun the selector on another FAIL.

Even if Codex implementer finishes with a positive message and all
local tests pass, it is **IMPLEMENTED_TESTED**, not VERIFIED_FIXED.
Independent reviewer PASS on the identical SHA + passing software and
browser/release gates + owner approval are required for release.
