# V0.3 Adaptive Repair Router — Herdr + cbds + Codex

Use this as the **current routing policy** for NEW owner-authorized campaigns.
It changes HOW approved defects are assigned; it does **not** approve a fresh
review campaign, extend review limits, merge to main, or deploy. Existing R004's
five-review ceiling remains exhausted. Keep its reports and state intact.

## Prerequisites

- Read the project's AGENTS.md, exact latest independently validated
  review.md / tickets.json, cbds status and review-loop gate state.
- Check source SHA against immutable review.md; never use a different
  worktree's ticket file. No overlapping active workers, duplicate dispatch,
  unclean integration checkout, or branch exposed to 6 AM auto-merging.
- Validate the raw review with scripts/validate-sol-tickets.py against the
  exact reviewed SHA and repo BEFORE trusting the exported tickets.json.
- Use the deterministic CLI selector; NEVER ask an LLM to eyeball the threshold:

  python3 /home/openclaw/agent-orchestration-lab/scripts/route-repair.py \
    --tickets /REAL/PATH/TO/validated/tickets.json \
    --state /REAL/PATH/TO/.cbds/review-loop-v02.json

  The --state argument is optional only when the latest matching state
  genuinely does not exist. If state and packet SHA disagree, STOP.
  --threshold defaults to 4. --force-multi is allowed for legitimately
  coupled tasks that need separate bounded file ownership.
  The selector is side-effect-free and cannot dispatch agents or spend tokens.

## Dynamic selection — enforce selector's route

- **NO_REPAIR / 0 outstanding:** Stop coding. Check other release gates;
  review PASS does not authorize deployment.
- **CODEX_DIRECT / 1 to 4 outstanding:** One Codex GPT-6.1 Sol High
  *implementation* process on a unique, isolated feature worktree.
  Use **workspace-write** sandbox and a concise prompt drawn only from real
  tickets. No AGY dispatch, multiple Codex processes, or broad codebase sweep.
  Give it full ticket reproduction, code paths, root causes, acceptance tests
  and regression requirements. Ask it to write a failing test before the fix
  when feasible, implement minimal root-cause fixes and run focused tests.
  Preserve exact token and report evidence. Codex must NEVER execute a
  reviewer from inside its implementation run and must not sign off its own work.
- **AGY_PARALLEL / 5+ outstanding:** Coordinator groups shared root causes
  and launches at most TWO disjoint AGY workers via real Herdr + cbds.
  Require accepted report IDs, commits and test evidence before integration.
  If a small batch spans risky overlapping ownership, use --force-multi;
  no automatic brittle assignment when ownership cannot be made exclusive.
- **MANUAL_TRIAGE / P0 or disputed:** Do not pretend requirements are
  determined. Preserve findings and ask for a concrete risk/behavior decision.
- **Selector BLOCKED:** Stop. Never work from malformed/stale tickets.

For a direct Codex implementation, *example* (write actual per-ticket prompt to
an existing file first; validate isolated checkout and safe test database):

  codex exec --model gpt-6.1-sol --sandbox workspace-write \
    -C /ABSOLUTE/ISOLATED/FEATURE/WORKTREE \
    --output-last-message /ABSOLUTE/SAFE/STATE/CODEX_IMPLEMENTATION.md \
    - < /ABSOLUTE/SAFE/STATE/CODEX_IMPLEMENTATION_PROMPT.md

The code-changing implementation is distinct from a separate **read-only**
independent reviewer using scripts/run-sol-review.sh after integration.
A CODEx implementation PASS or passing local tests NEVER becomes review PASS.

## Shared verification and state

1. Compare changed files against task scope. Run focused reproducible
   regressions. No production DB, force push, main merge, account data edits,
   or destructive commands. Real Postgres concurrency checks must use test DB.
2. After integrated SHA is clean, rerun full deterministic tests, typecheck,
   build, scheduler/finance/security/life-hub gates and browser checks if
   available. Mark NOT_RUN honestly. A failing local gate triggers repair,
   not an independent review.
3. Record immutable implementation SHA, exact test output, ticket dispositions
   as IMPLEMENTED_TESTED (not VERIFIED_FIXED), changed files and provenance:
   cbds IDs for AGY route; Codex run log/evidence for direct route.
4. Once software gates PASS, independent Sol reviewer checks **exact NEW SHA**
   in read-only ticket mode and prior-ticket ledger. It may find new issues;
   run selector again on the validated result. Repeat ONLY under a currently
   owner-authorized, unexhausted review budget and with a NEW code SHA.
5. Persist review round count via review-loop-gate.py; do not reset 5/5
   campaigns, alter previous review verdicts or accept an invalid packet.
6. Final PASS requires separate reviewer PASS, all tracked blocking tickets
   VERIFIED_FIXED, all required release gates and explicit owner approval
   before merging or production deployment.

## Decision contract

Input: validated packet schema 1.0 and optional matching review-loop-v02.json.

Output JSON:
- route: NO_REPAIR / CODEX_DIRECT / AGY_PARALLEL / MANUAL_TRIAGE
- ticket_ids and unresolved_count (deduplicates findings and prior OPEN tickets)
- implementation_model and implementation_sandbox when direct
- review_budget.exhausted; always false for review_authorized_by_this_router
- may_merge_or_deploy = false

Never infer safety from a route. Threshold routing reduces worker handoffs;
it does not promise to save a given percentage of tokens.
