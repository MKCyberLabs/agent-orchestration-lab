# Agent Orchestration Lab V0.2 — reviewer reliability & recovery

Status: **implementation candidate; not validated on OpenClaw**. V0.1 (T001–T003) is validated. Do not declare V0.2 PASS until the physical host gates below pass.

## R001 lessons

- Gemini 3.8 Flash High can coordinate two independently isolated AGY workers through cbds durable reporting.
- Terminal/pane status and an idle shell are **not** evidence that work or review succeeded.
- Codex interactive Herdr startup failed due to shared daemon/model discovery; `--no-daemon` addressed one startup mode but was not durable across dispatches.
- Standalone `codex exec` started correctly, but its Linux read-only sandbox failed before even `git rev-parse HEAD`: `bwrap: loopback: Failed RTM_NEWADDR: Operation not permitted`.
- An LLM repeatedly saying "still waiting" and repeatedly checking a task manager wastes orchestration tokens. Use exactly one bounded cbds wait per pending state transition; a timeout is a checkpoint, not success.
- Long-running orchestration sessions disappeared under tmux. Durable Git and cbds state survived. Recovery should use them, not huge prior chat histories.
- V0.1 global npm cbds files were manually edited during recovery; **do not patch node_modules** in V0.2.

## Reliability requirements

1. Before any Codex dispatch, run `bash scripts/preflight-codex-reviewer.sh` **without LLM involvement**. A failed preflight yields BLOCKED, not an attempted LLM review.
2. The Sol review uses `codex --profile sol-review exec ...`; **do not send an interactive Codex session to Herdr** until an independent startup/health test proves it safe.
3. `scripts/run-sol-review.sh` always pins the actual Git commit, stores a bounded report outside the source tree, and refuses to mark unreviewed code PASS.
4. An independent code-review FAIL is a *successful transport/result* carrying `VERDICT: FAIL`—not proof the reviewer crashed. BLOCKED means it could not review.
5. For cbds reporting, inject `CBDS_TASK_ID` and `CBDS_DISPATCH_ID` via a real cbds-managed shell/pane; NEVER spoof task identity.
6. One orchestrator per run. Recover same run after restart; check current run, reports, task authority and current Git HEAD before dispatching anything.
7. A completion report cannot approve code changed after the report's pinned SHA. Re-run review after repairs.
8. No worker may write to production credentials, production databases or the default branch. No auto-merges.
9. Role instructions belong in project AGENTS.md + skill. Only generic cli reviewer profile belongs under a user's `~/.codex/config.toml`.
10. Do not weaken host-wide AppArmor/user namespace sysctls or use `danger-full-access` merely to make a reviewer work.

## Milestones & gates

- **G0 Baseline:** preserve T001–T003 and R001 evidence; confirm `git status`, current branch, cbds 2.3.0 installed code matches upstream, Herdr server health.
- **G1 Reviewer launch:** profile install is idempotent, CLI identity stable, `/usr/bin/bwrap` or equivalent correctly configured, token-free sandbox preflight executes `/bin/true`.
- **G2 Read-only review:** standalone runner reads a fixture repo, pins HEAD, returns structured PASS and detects mismatched SHA; verify no source changes.
- **G3 Negative paths:** absent bwrap, sandbox EPERM, CLI auth error, missing verdict, timeout -> BLOCKED durable report with no duplicate dispatch; reviewer code FAIL -> accepted transport report with verdict FAIL.
- **G4 cbds bridge:** a *cbds-created* bare-shell worker receives its environment, executes the review runner, and `cbds wait` returns one authoritative report. **The exact Herdr shell-prompt/run adapter must be proved on installed Herdr 0.9.1 before production use**.
- **G5 Crash recovery:** kill orchestrator while worker continues; restart fresh orchestrator; collect stored result without duplicate tasks or retrying a completed dispatch.
- **G6 End-to-end:** independently review NutriSnap R001 HEAD (or a current follow-up commit), run all required finance/reminder/security/test/build gates in an appropriately provisioned environment, publish signed-off evidence and metrics.
- **G7 Promotion:** review branch and merge V0.2 into lab main ONLY after G0–G6 evidence, and install generic skill globally if desired.
